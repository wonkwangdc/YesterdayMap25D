# 수면 규칙 인수인계

작성 기준: 2026-08-07  
대상 프로젝트: 《어제의 지도》 Unity 6000.3.20f1

## 1. 문서 목적

이 문서는 현재 확정된 수면 규칙과 예외 처리, 스토리 진행 조건, 저장 데이터 및 코드 연결 지점을 정리한 인수인계 문서다.

핵심 원칙은 다음 두 가지다.

- **3분기 엔딩 선택일:** 엔딩을 선택하기 전에는 절대로 잠들 수 없다.
- **마지막 벙커:** 조건을 채우지 않아도 잠은 잘 수 있지만, 마지막 벙커의 이야기 일차는 진행되지 않는다.

즉, 3분기 엔딩 선택일은 **수면 차단**, 마지막 벙커의 미완료 조건은 **스토리 진행 보류**로 서로 다르게 처리한다.

## 2. 수면 판정 우선순위

침대 상호작용 시 아래 순서대로 판정한다. 위에서 조건이 확정되면 아래 판정은 실행하지 않는다.

| 우선순위 | 조건 | 수면 가능 여부 | 처리 |
|---:|---|---|---|
| 1 | 침대가 고장 났거나 이미 수면 처리 중 | 불가 | 기존 시설/중복 실행 방지 처리 |
| 2 | 3분기 엔딩 선택일 | 불가 | 이벤트 대화 UI로 `더 이상 지체할 시간이 없어.` 출력 |
| 3 | 마지막 벙커 이야기 진행 조건 미충족 | 가능 | 미충족 항목과 이야기 보류 사실을 경고한 뒤 플레이어가 선택 |
| 4 | 3분기 1~4일차 단서 행동 미완료 | 가능 | 잠들면 해당 단서 기회를 잃는다는 경고 후 선택 |
| 5 | 체력 0 빈사 상태의 재수면 | 선택 후 사망 | 사망 확인창 출력 후 치명적 수면 처리 |
| 6 | 그 외 일반 상황 | 가능 | 일반 수면 확인창 출력 |

3분기 엔딩 선택일 차단은 빈사 상태의 사망 확인보다 먼저 판정한다. 따라서 엔딩 선택일에는 체력이 0이어도 침대에서 사망 수면으로 넘어가지 않으며, 먼저 엔딩을 선택해야 한다.

## 3. 일반 수면 흐름

일반 수면은 다음 순서로 진행된다.

1. 수면 확인
2. 수면 연출 및 화면 전환
3. 수면 스탯 감소
4. 야간 사건 판정
5. 생존 중이면 날짜 증가
6. 다음 날 아침 굶주림·탈수·빈사 상태 판정
7. 날짜 변경 이벤트 및 스토리 상태 동기화
8. 사기 5 회복

수면 시 기본 스탯 변화:

| 스탯 | 변화량 |
|---|---:|
| 굶주림 | -20 |
| 갈증 | -30 |
| 정신력 | -10 |
| 정상적으로 다음 날에 도달했을 때 정신력 | +5 |

체력 0 빈사 상태에서 사망 수면을 선택한 경우에는 일반 수면 스탯 감소와 날짜 진행을 실행하지 않고 `FatalInjury` 사망을 처리한다.

## 4. 아침 생존 경고 대사

굶주림과 탈수의 기존 경고·사망 규칙은 유지한다. 아침 혼잣말은 자막이 아니라 기존 **이벤트 대화 UI**를 사용한다.

| 상태 | 대사 |
|---|---|
| 굶주림 1차 경고 | `배고프다… 오늘은 뭐라도 좀 먹어야겠는데.` |
| 굶주림 2차 경고 | `힘이 하나도 없네… 이대로 하루 더 버티는 건 무리야.` |
| 탈수 1차 경고 | `목이 너무 마르네… 물부터 좀 마셔야겠다.` |
| 탈수 2차 경고 | `입안이 다 말랐어… 진짜 더는 못 버티겠다.` |

두 상태가 동시에 발생하면 대사를 한 줄씩 순서대로 출력한다. 다음 대사가 남아 있으면 버튼은 `다음`, 마지막 줄에서는 `확인`을 사용한다. 대화가 모두 끝난 뒤 기존 시스템 경고 문구가 보이도록 한다.

### 3분기 엔딩 선택일 예외

3분기 엔딩 선택일에는 다음 날이 존재하면 안 되므로 굶주림·탈수 **혼잣말만 출력하지 않는다**. 스탯 값이나 생존 판정 규칙 자체를 삭제하거나 초기화하는 것은 아니다.

대신 계열별 엔딩 선택 안내 혼잣말을 한 번 출력한다.

구조신호 계열:

1. `오늘 두 주파수에서 마지막 집결 안내를 보내겠다고 했지.`
2. `마지막 방송까지 듣고… 어느 쪽을 믿을지 결정해야 한다.`

합류 계열:

1. `오늘 아침, 두 무리 모두 거점을 떠난다고 했지.`
2. `두 무리의 마지막 입장을 확인하고… 누구와 함께 갈지 결정해야 한다.`

이 안내도 이벤트 대화 UI를 사용하고, 저장 후 불러오더라도 이미 확인했다면 반복 출력하지 않는다.

## 5. 분기별 수면 규칙

### 5.1 1분기

1분기는 기존 수면 및 날짜 진행 규칙을 유지한다. 이번 수면 패치에서 별도의 강제 수면 차단 조건을 추가하지 않았다. 12일차 도달 후 2분기로 넘어가는 기존 흐름을 그대로 사용한다.

### 5.2 2분기

2분기도 기존 이벤트 진행 상태를 그대로 기준으로 삼는다. 이번 수면 패치에서 별도의 강제 수면 차단 조건을 추가하지 않았다. 이벤트를 확인하지 않은 상태에서는 해당 이벤트/스토리 단계가 지연되는 기존 방식으로 처리한다.

### 5.3 3분기 1~4일차

- 오늘의 스토리를 먼저 확인해야 다른 주요 행동을 진행할 수 있는 기존 흐름을 유지한다.
- 구조신호 계열의 미완료 탐사 단서 또는 합류 계열의 미완료 지원 행동이 남아 있는 상태에서도 잠은 잘 수 있다.
- 단, 잠들기 전에 해당 단서 기회를 잃는다는 경고를 표시한다.
- 플레이어가 경고를 승인하고 잠들면 다음 날로 넘어가며, 놓친 당일 기회는 다시 제공하지 않는다.

### 5.4 3분기 엔딩 선택일

두 계열 모두 3분기 로컬 5일차 이상을 엔딩 선택 단계로 취급한다.

공통 규칙:

- 탐사를 막는다.
- 엔딩 선택 전에는 수면을 완전히 막는다.
- 오늘의 스토리를 아직 확인하지 않았더라도 잠을 잘 수 없다.
- 오늘의 스토리를 확인했더라도 엔딩을 선택하기 전에는 잠을 잘 수 없다.
- 침대를 사용하면 이벤트 대화 UI로 `더 이상 지체할 시간이 없어.`를 출력한다.
- `확인`을 누르면 대화만 닫히며 수면 연출, 스탯 감소, 날짜 증가는 발생하지 않는다.
- 저장/불러오기 후에도 최종 스토리 확인 상태와 엔딩 선택 대기 상태를 유지한다.

구조신호 계열 진행 순서:

1. 아침 엔딩 안내 혼잣말
2. 책상에서 `[T] 오늘의 스토리 확인`
3. 마지막 방송 내용 확인
4. 문에서 `[T] 엔딩을 고르세요`
5. 엔딩 선택

합류 계열 진행 순서:

1. 아침 엔딩 안내 혼잣말
2. 문 앞에서 메인 일기의 스토리를 확인하라는 안내
3. 일기장을 열어 마지막 스토리 확인
4. 문에서 `[T] 엔딩을 고르세요`
5. 엔딩 선택

## 6. 마지막 벙커 수면 규칙

마지막 벙커는 실제 생존 날짜와 별도로 `마지막 벙커 이야기 일차`를 관리한다.

- 실제 날짜: 정상 수면을 하면 계속 증가한다.
- 마지막 벙커 이야기 일차: 그날의 필수 조건을 모두 채운 뒤 잠들어야 증가한다.

### 6.1 일차별 필수 조건

| 마지막 벙커 이야기 일차 | 오늘의 일기 생성 | 문 앞 고정 이벤트 완료 | 다음 이야기 진행 조건 |
|---:|:---:|:---:|---|
| 1일차 | 필수 | 없음 | 일기 생성 후 수면 |
| 2일차 | 필수 | 없음 | 일기 생성 후 수면 |
| 3일차 | 필수 | 없음 | 일기 생성 후 수면 |
| 4일차 | 필수 | 없음 | 일기 생성 후 수면 |
| 5일차 | 필수 | 필수 | 두 조건 완료 후 수면 |
| 6일차 | 필수 | 필수 | 두 조건 완료 후 수면 |
| 7일차 | 필수 | 필수 | 두 조건 완료 후 수면 |
| 8일차 | 필수 | 없음 | 일기 생성 후 수면 |
| 9일차 | 필수 | 필수 | 두 조건 완료 후 수면 |

오늘의 일기는 탐사를 완료해 생성한다. 일기장을 실제로 열어 읽는 행위는 진행 조건이 아니다. 새 일기가 추가되면 일기장이 빛나는 기존 알림으로 안내하며, 읽지 않은 책임은 플레이어에게 둔다.

마지막 벙커의 일반 랜덤 이벤트는 필수 조건이 아니며, 이야기 일차 진행을 막지 않는다.

### 6.2 조건을 채우지 않고 잠드는 경우

조건 미충족 상태에서도 플레이어는 경고창에서 `잠자기`를 선택할 수 있다.

- 일반 수면 스탯 변화와 실제 날짜 진행은 정상 적용된다.
- 마지막 벙커 이야기 일차는 현재 단계에 머문다.
- 이미 완료한 일기 또는 고정 이벤트 상태는 저장된다.
- 다음 실제 날짜에 완료하지 못한 항목만 채우면 된다.
- 고정 이벤트와 일기를 모두 다시 할 필요는 없다.

경고 문구:

| 미충족 상태 | 안내 문구 |
|---|---|
| 일기와 고정 이벤트 모두 미완료 | `오늘의 일기를 생성하고 문 앞의 고정 이벤트를 완료해야 다음 이야기가 진행됩니다.` |
| 일기만 미완료 | `탐사를 통해 오늘의 일기를 생성해야 다음 이야기가 진행됩니다.` |
| 고정 이벤트만 미완료 | `문 앞의 고정 이벤트를 완료해야 다음 이야기가 진행됩니다.` |

경고 뒤에는 공통으로 다음 문구를 덧붙인다.

`지금 잠들면 마지막 벙커 이야기는 현재 단계에 머뭅니다.`

버튼은 `잠자기`와 `취소`를 사용한다.

### 6.3 조건을 모두 채우고 잠드는 경우

- 정상 수면 및 실제 날짜 증가를 처리한다.
- 날짜 변경 뒤 마지막 벙커 이야기 일차를 1 증가시킨다.
- 치명적 수면으로 사망한 경우에는 이야기 일차를 증가시키지 않는다.
- 9일차 조건을 완료하고 정상적으로 잠들면 내부 이야기 일차는 10이 된다.

마지막 벙커 9일차 이후의 별도 엔딩은 아직 추가 예정 사항이다. 엔딩 구현 전까지 `이야기 일차 10`을 새로운 일반 일차 콘텐츠로 오해해 사용하지 않는다.

- 마지막 벙커에서 일기만 완료하거나 고정 이벤트만 완료한 부분 진행 상태

## 9. 필수 회귀 테스트

### 일반 수면

- 일반 날짜에 `잠자기` 승인/취소가 정상 동작하는지 확인
- 수면 스탯 감소, 야간 사건, 날짜 증가, 아침 판정 순서 확인
- 체력 0 빈사 상태에서 재수면 승인 시 날짜가 증가하지 않고 사망하는지 확인

### 아침 생존 대사

- 굶주림과 탈수 1·2차 대사가 올바른 단계에 출력되는지 확인
- 두 상태가 동시에 발생하면 모든 대사가 한 줄씩 이어지는지 확인
- 마지막 줄만 `확인`, 그 전에는 `다음` 버튼인지 확인

### 3분기 1~4일차

- 단서 행동 미완료 상태에서 수면 경고가 출력되는지 확인
- 승인하면 다음 날로 넘어가고 당일 단서 기회가 종료되는지 확인
- 취소하면 현재 날짜와 단서 기회가 유지되는지 확인

### 3분기 엔딩 선택일

- 구조신호와 합류 계열 모두 침대 사용 시 수면이 차단되는지 확인
- 마지막 스토리 확인 전과 후 모두 동일하게 차단되는지 확인
- 체력 0이어도 치명적 수면 확인창보다 엔딩일 차단 대사가 먼저 나오는지 확인
- 침대 대화 확인 후 수면 연출, 스탯 감소, 날짜 증가가 없는지 확인
- 엔딩 선택일에는 굶주림·탈수 혼잣말이 나오지 않는지 확인
- 계열별 두 줄짜리 아침 엔딩 안내가 한 번만 나오는지 확인
- 저장/불러오기 후 마지막 스토리 확인 및 엔딩 선택 대기 상태가 유지되는지 확인

### 마지막 벙커

- 1~4·8일차에는 일기 생성만으로 이야기 진행 조건을 만족하는지 확인
- 5·6·7·9일차에는 일기와 고정 이벤트가 모두 필요함을 확인
- 둘 다 미완료, 일기만 완료, 이벤트만 완료, 둘 다 완료한 네 상태를 각각 확인
- 조건 미충족 수면 시 실제 날짜만 증가하고 이야기 일차는 유지되는지 확인
- 부분 완료 상태에서 저장/불러오기 후 완료 상태가 유지되는지 확인
- 일기장을 열지 않아도 일기가 생성되어 있으면 조건을 만족하는지 확인
- 일반 랜덤 이벤트 미확인이 이야기 진행을 막지 않는지 확인
- 치명적 수면 사망 시 이야기 일차가 증가하지 않는지 확인

## 10. 변경 시 지켜야 할 기준

- 3분기 엔딩 선택일을 일반 수면이나 치명적 수면으로 우회할 수 있게 만들지 않는다.
- 마지막 벙커 조건 미충족을 수면 자체의 강제 차단으로 바꾸지 않는다.
- 실제 날짜와 마지막 벙커 이야기 일차를 다시 하나의 값으로 합치지 않는다.
- 마지막 벙커의 부분 완료 상태를 날짜가 바뀔 때 초기화하지 않는다.
- 굶주림·탈수 경고 대사 UI와 엔딩 안내 대사는 자막 UI로 옮기지 않는다.
- 새로운 수면 예외를 추가할 때는 `BedObject.Interact()`의 우선순위와 저장/불러오기 영향을 함께 검토한다.
