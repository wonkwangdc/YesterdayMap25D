# 어제의 지도 (YesterdayMap25D)

G-Star 후보작품 제출용 소스 프로젝트의 설치 및 실행 안내입니다.

《어제의 지도》는 재난 이후 제한 시간 안에 물자를 모으고, 벙커에서 자원과 생존 상태를 관리하며 탐사와 사건을 통해 이야기를 이어가는 싱글 플레이 생존 게임입니다. 현재 프로젝트는 **3D 공간을 1인칭 시점으로 이동**하는 방식이며, 게임 화면과 안내는 한국어로 제공됩니다.

- 프로젝트명: `YesterdayMap25D`
- 개발 엔진 / 언어: Unity `6000.3.20f1` / C#
- 실행 기준 플랫폼: Windows PC, 키보드와 마우스
- 기본 실행 방법: Unity Editor에서 `MainMenu` 씬을 열고 Play
- 문서 기준일: 2026-09-17, 현재 프로젝트의 소스 코드 및 씬 설정 기준

## 1. 빠른 실행 안내

Unity와 Git이 이미 설치되어 있다면 다음 순서로 실행할 수 있습니다.

1. 제출받은 프로젝트 전체를 압축 해제합니다.
2. Unity Hub에서 **추가(Add) → 디스크에서 프로젝트 추가(Add project from disk)**를 선택합니다.
3. `Assets`, `Packages`, `ProjectSettings`가 들어 있는 프로젝트 최상위 폴더를 선택합니다.
4. **Unity 6000.3.20f1**로 열고 패키지 설치와 에셋 임포트가 완료될 때까지 기다립니다.
5. Project 창에서 `Assets/_Project/Scenes/MainMenu.unity`를 더블클릭합니다.
6. Editor 상단의 **Play(▶)**를 누르고 **Game** 탭을 클릭합니다.
7. **새로운 생존 시작**을 선택하고 이름을 입력하면 게임이 시작됩니다.

처음 실행하는 PC에서는 아래의 설치 절차부터 진행해 주세요.

## 3. 설치 방법

### 3.1. Unity 설치

1. [Unity 다운로드 페이지](https://unity.com/download)에서 Unity Hub를 설치합니다.
2. Hub의 안내에 따라 로그인과 Editor 사용에 필요한 라이선스 설정을 완료합니다.
3. Unity Editor **6000.3.20f1**을 설치합니다. Hub의 기본 목록에 없다면 [Unity Editor 다운로드 아카이브](https://unity.com/releases/editor/archive)에서 해당 버전을 찾아 Hub로 설치합니다.
4. 프로젝트를 열 때 다른 버전으로 업그레이드하지 않고 **6000.3.20f1**을 선택합니다.

Editor에서 플레이하는 데에는 별도의 Windows 실행 파일 빌드가 필요하지 않습니다. Windows 빌드에 필요한 플랫폼 모듈이 없다는 안내가 나오면 Build Profiles의 **Install with Unity Hub** 안내에 따라 추가합니다.

### 3.2. Git 설치

프로젝트에는 Git 저장소에서 가져오는 Unity 패키지가 있어 Git 실행 파일이 필요합니다.

1. [Git for Windows 공식 설치 페이지](https://git-scm.com/install/windows)에서 Git을 설치합니다.
2. 설치 옵션에서 다른 프로그램도 Git을 사용할 수 있도록 PATH 등록을 허용합니다.
3. PowerShell을 새로 열고 다음 명령으로 설치를 확인합니다.

   ```powershell
   git --version
   ```

4. 버전이 표시되면 Unity Hub와 Unity Editor를 다시 실행합니다.

Unity Package Manager의 Git 의존성 요구 사항은 [공식 안내](https://docs.unity3d.com/6000.3/Documentation/Manual/upm-git.html)를 참고할 수 있습니다.

### 3.3. 프로젝트 열기와 패키지 복원

1. 압축 파일 내부에서 직접 열지 말고 프로젝트 전체를 로컬 폴더에 압축 해제합니다. 경로 예시는 `C:\Projects\YesterdayMap25D`입니다.
2. Unity Hub에 프로젝트 최상위 폴더를 추가하고 지정된 Editor 버전으로 엽니다.
3. 최초 실행 시 Unity가 `Packages/manifest.json`과 `Packages/packages-lock.json`을 읽어 의존성을 복원하고 `Library`를 생성합니다. 이 과정에는 시간이 걸릴 수 있습니다.
4. 임포트와 스크립트 컴파일이 완료되면 **Window → General → Console**에서 빨간 오류가 없는지 확인합니다.
5. `MainMenu.unity`를 열고 실행합니다.

`Assets` 내부의 `.meta` 파일과 두 패키지 JSON 파일을 함께 유지해야 에셋 연결과 패키지 버전이 보존됩니다. 개별 패키지를 임의로 최신 버전으로 교체할 필요는 없습니다.

## 4. 게임 시작과 진행 방법

### 4.1. 메인 메뉴와 프롤로그

- **새로운 생존 시작**: 새 게임을 시작합니다.
- **이어서 하기**: 다섯 저장 슬롯 중 가장 최근에 저장된 데이터를 불러옵니다. 저장 데이터가 없는 첫 실행에서는 **새로운 생존 시작**을 선택합니다.
- **생존 기록**: 생존 기록 화면을 엽니다.
- **설정**: 화면, 조작 등의 설정을 변경합니다.
- **게임 종료**: 실행 파일에서는 게임을 종료하며, Editor에서는 Play 모드를 종료합니다.

새 게임을 시작하면 주인공 이름을 입력하고 **확인** 또는 **Enter**를 누릅니다. 이름은 최대 8자이며 빈 이름으로는 시작할 수 없습니다. 프롤로그는 화면 안내에 따라 **Space 또는 마우스 좌클릭**으로 진행합니다.

### 4.2. 물자 수집 — Scavenge

1. **60초** 안에 집 안의 물자를 모아 벙커로 이동합니다.
2. 물자에 가까이 다가가 화면 중앙으로 겨냥하고 **E**를 눌러 줍습니다.
3. 한 번에 운반할 수 있는 물자는 **최대 4개**입니다.
4. 벙커 입구에서 **E를 눌러 운반 중인 물자를 반입**합니다. 반입 후 가방이 비워지므로 남은 시간 동안 다시 물자를 모을 수 있습니다.
5. 수집을 마치면 입구에서 **E로 마지막 물자까지 반입한 뒤 F를 눌러 벙커에 진입**합니다.

**F는 벙커 진입 기능이며, 손에 든 물자를 자동으로 반입하지 않습니다. E로 반입을 먼저 완료해 주세요.** 제한 시간이 끝날 때까지 벙커에 들어가지 못하면 암전 후 게임 오버가 됩니다.

### 4.3. 벙커 생활 — Shelter

벙커에서는 식량·식수 등의 자원과 체력·배고픔·갈증·정신력을 관리하며 하루를 보냅니다. 가까운 시설을 바라보면 화면에 해당 시설의 조작 안내가 표시됩니다.

첫날에는 화면의 튜토리얼 목표에 따라 다음 순서로 진행합니다.

1. **Q 또는 Tab**으로 일기를 확인합니다.
2. 선반 앞에서 **F**로 창고를 열어 보유 물자를 확인합니다.
3. 식량·식수 선반 앞에서 **E**로 음식과 물을 사용합니다.
4. 연료 선반에서 **E**로 연료통을 든 뒤 발전기에 가져가 **F**로 투입합니다.
5. 필요한 목표를 마친 뒤 침대에서 **E**를 누르고 수면을 확인하여 다음 날로 넘어갑니다.

첫날 목표를 완료하기 전에는 수면이 제한됩니다. 발전기는 **E**로 가동·정지하며, 연료 투입은 잔량이 **75% 이하**일 때 가능합니다. 연료통 한 개를 투입하면 **25%**가 충전됩니다.

### 4.4. 탐사와 사건

- 탐사는 **2일차부터 하루 한 번**, 벙커 출입구에서 **E**로 시작합니다.
- 지도에서 장소와 위험도, 장비 및 상태를 확인하고 화면 안내에 따라 출발합니다.
- 탐사 결과에 따라 자원을 얻거나 부상과 사건이 발생할 수 있습니다.
- 문 앞 사건은 안내가 표시될 때 **T**로 진행합니다.
- 일기에서 생존 상태, 자원, 탐사 기록과 단서를 확인할 수 있습니다.
- 자원 관리와 사건의 선택에 따라 생존과 이야기의 결말이 달라집니다.

## 6. 저장과 불러오기

- 수동 저장은 **벙커 안에서** 가능합니다.
- **Esc → 저장하기 → 1~5번 슬롯 선택 → 예**로 저장합니다.
- **Esc → 불러오기 → 슬롯 선택 → 예**로 해당 데이터를 불러옵니다.
- 날짜가 바뀔 때 **현재 선택된 슬롯**에 자동 저장됩니다. 처음에는 1번 슬롯이 선택됩니다.
- 메인 메뉴의 **이어서 하기**는 저장 시각이 가장 최근인 슬롯을 불러옵니다.
- 기존 플레이를 남기려면 새 플레이를 저장할 때 다른 슬롯을 선택해 주세요.

현재 프로젝트 설정에서 Windows 저장 경로는 다음과 같습니다. 탐색기 주소 표시줄에 입력하면 열 수 있습니다.

```text
%USERPROFILE%\AppData\LocalLow\ysw_cp\60sec
```

슬롯 파일 이름은 `save_slot_01.json`부터 `save_slot_05.json`까지입니다. 저장 폴더의 `60sec`는 내부 Product Name이며, 표시되는 게임 제목과 다릅니다. 저장 데이터는 프로젝트 폴더가 아닌 사용자 PC의 이 경로에 기록됩니다.

## 7. 씬 구성과 주요 소스

Build Profiles의 Scene List에는 다음 다섯 씬이 아래 순서로 포함되어 있습니다.

| 순서 | 씬 경로 | 역할 |
| --- | --- | --- |
| 0 | `Assets/_Project/Scenes/MainMenu.unity` | 메인 메뉴와 시작점 |
| 1 | `Assets/_Project/Scenes/Prologue.unity` | 이름 입력과 도입부 |
| 2 | `Assets/_Project/Scenes/Scavenge.unity` | 제한 시간 물자 수집 |
| 3 | `Assets/_Project/Scenes/Shelter.unity` | 벙커 생활, 저장, 날짜 진행 |
| 4 | `Assets/_Project/Scenes/Exploration.unity` | 벙커에서 추가 로드되는 탐사 화면 |

일반 플레이는 **MainMenu에서 시작**합니다. Exploration은 벙커 진행 중 추가로 로드되는 씬이므로 단독으로 열어 플레이하는 방식으로 시작하지 않습니다.

```text
YesterdayMap25D/
├─ Assets/                     게임 에셋과 .meta 파일 전체
│  └─ _Project/
│     ├─ Scenes/               플레이 씬
│     ├─ Scripts/              게임 C# 소스
│     ├─ Prefabs/              캐릭터, 시설, 환경, UI 프리팹
│     ├─ Art/                  모델, 이미지, 텍스처
│     ├─ Audio/                오디오 리소스
│     ├─ Animations/           애니메이션
│     ├─ Data/                 게임 데이터
│     ├─ Materials/            머티리얼
│     └─ Editor/               Editor용 제작·검증 도구
├─ Packages/
│  ├─ manifest.json           패키지 의존성
│  └─ packages-lock.json      복원에 사용할 패키지 버전 정보
├─ ProjectSettings/           엔진 버전, 입력, 빌드 등의 프로젝트 설정
├─ Docs/                      기획 및 개발 문서
└─ README.md                  본 설치·실행 안내
```

소스의 주요 책임은 `Scripts/Core`의 게임 흐름·저장, `Character`의 이동·상태, `Scavenge`의 수집, `Shelter`의 시설, `Resources`의 자원, `Exploration`의 탐사, `Events`의 사건, `UI`의 화면으로 나뉩니다.

소스를 전달할 때에는 **Assets 전체와 .meta 파일, Packages, ProjectSettings, README.md**를 함께 포함해야 합니다. `Library`, `Temp`, `Obj`, `Logs`, `UserSettings`와 IDE 임시 파일은 Unity가 생성하는 캐시·개인 설정이며 소스 복원에 필수인 파일은 아닙니다.

### 주요 패키지

| 패키지 | manifest 기준 버전 또는 공급 방식 |
| --- | --- |
| Input System | 1.17.0 |
| AI Navigation | 2.0.13 |
| Universal Render Pipeline | 17.3.0 |

## 8. Windows 실행 파일 만들기와 실행

현재 소스를 독립 실행 파일로 확인하려면 다음 절차로 새로 빌드합니다. 프로젝트에 남아 있는 `Builds/Windows/YesterdayMap25D.exe`는 **2026-08-04에 기록된 과거 개발 빌드**이므로 이 문서 기준의 현재 소스 실행본으로 사용하지 않습니다.

1. Unity의 Play 모드를 종료합니다.
2. **File → Build Profiles**를 엽니다.
3. Windows 플랫폼을 선택합니다. 프로필이 없다면 **Add Build Profile → Windows → Add Build Profile**로 만든 뒤 **Switch Profile**로 활성화합니다.
4. 필요한 플랫폼 모듈이 없으면 **Install with Unity Hub**로 설치합니다.
5. Windows 아키텍처를 **Intel 64-bit / x86_64**로 설정합니다.
6. Scene List에서 7절의 다섯 씬이 모두 활성화되어 있고 `MainMenu`가 첫 번째인지 확인합니다. 프로필별 Scene List를 사용한다면 해당 목록도 동일하게 맞춥니다.
7. 일반 배포용으로는 **Development Build**를 해제합니다.
8. **Build** 또는 **Build And Run**을 선택합니다. 출력 폴더 예시는 `Builds/SubmissionWindows`, 실행 파일명 예시는 `YesterdayMap25D.exe`입니다.
9. 빌드가 완료되면 출력 폴더의 실행 파일을 더블클릭합니다. 실행 파일을 받는 PC에는 Unity Editor가 필요하지 않습니다.

실행 파일을 이동하거나 전달할 때는 **출력 폴더 전체**를 함께 전달합니다. `.exe`만 복사하면 실행에 필요한 데이터와 라이브러리를 찾지 못할 수 있습니다. `YesterdayMap25D_Data`, `UnityPlayer.dll` 및 함께 생성된 하위 폴더를 유지해 주세요.

상세한 프로필 설정은 [Unity Build Profiles 공식 안내](https://docs.unity3d.com/6000.3/Documentation/Manual/create-build-profile.html)를 참고할 수 있습니다.

## 9. 실행 중 문제가 있을 때

| 증상 | 확인 및 해결 방법 |
| --- | --- |
| Hub에서 프로젝트로 인식되지 않음 | `Assets`가 아닌, `Assets`·`Packages`·`ProjectSettings`를 포함하는 상위 폴더를 선택합니다. |
| Editor 버전이 다르다는 안내 | `ProjectVersion.txt`의 6000.3.20f1을 설치하고 그 버전으로 엽니다. |
| Git을 찾을 수 없거나 Git 패키지 설치 실패 | 새 PowerShell에서 `git --version`을 확인하고 Unity Hub·Editor를 다시 실행합니다. 인터넷 및 GitHub 접근도 확인합니다. |
| 최초 실행 시 임포트가 오래 걸림 | 패키지와 에셋 임포트가 완료될 때까지 기다립니다. 작업 중인 Unity 프로세스를 강제로 종료하지 않습니다. |
| Play가 시작되지 않음 | Console의 첫 번째 빨간 오류를 확인합니다. 먼저 패키지 복원과 Editor 버전, 제출 파일 누락 여부를 확인합니다. |
| 이동이나 마우스 시점 조작이 안 됨 | Game 탭의 게임 화면을 클릭합니다. UI가 열려 있다면 닫고, 설정에서 현재 이동 키를 확인합니다. |
| 물자를 더 주울 수 없음 | 운반 한도는 4개입니다. 입구에서 E로 반입한 뒤 다시 수집합니다. |
| 벙커에서 물자가 보이지 않음 | 수집 구간에서 F 진입 전에 E로 반입했는지 확인합니다. |
| 첫날 침대에서 잘 수 없음 | 일기·창고·섭취·연료 등 화면에 남은 튜토리얼 목표를 완료합니다. |
| 발전기에 연료가 들어가지 않음 | 연료 선반에서 연료통을 먼저 들고, 발전기 잔량이 75% 이하인지 확인한 뒤 F를 누릅니다. |
| 이어서 하기가 되지 않음 | 해당 PC에 저장 파일이 있는지 확인합니다. 첫 실행이라면 새로운 생존 시작을 선택합니다. |
| 실행 파일에서 DLL 또는 데이터 오류 | 빌드 출력 폴더 전체가 함께 있는지 확인하고 `.exe`만 분리하지 않습니다. |

제작용 메뉴 **Yesterday Map → Build v0.2 2.5D Project**는 씬·프리팹을 다시 생성하는 도구입니다. 게임 실행이나 Windows 빌드에 필요한 메뉴가 아니며, 기존 씬 내용을 재구성하므로 단순 실행 확인을 위해 사용하지 않습니다.
